## Terminal results remain bounded and recoverable

Control callbacks now write completed results into their existing bounded pending mailboxes. The realtime owner flushes them to the six-slot ACK outbox. An outbox-full condition keeps the result for the next cycle instead of discarding it. Completed results are not expired while waiting for space; timestamps and ACK key stay with the result. Neither callback performs network I/O.

The eight-second UI/device timeout is uncertainty, not cancellation or proof of rejection. Correlation is retained for a maximum 120-second reconciliation window for late completion. Pending slots are released after a completed result is queued or the bounded unknown window expires. Full tracking returns busy before any new remote execution. This does not alter command validity, actuator leases, local safety or watchdog policy.

Uncertain ACKs no longer enter the terminal cache. Exact terminal replay updates one existing record using a separate copy, preserving the 16-slot cache and avoiding aliased writes. Actual cache tests replay the result 100 times without evicting other entries; the mutation that caches uncertainty fails.

HMI queue defaults and local calls retain their behavior. Only optional remote admission/defer hooks changed; PID/controller/output/turning/alarm/batch/EEPROM schema/RTC/HMI display/ATtiny/boot/recovery/OTA fingerprints remain unchanged. The firmware's added global bookkeeping is approximately 408 bytes; actual TLS heap/task stack/jitter still needs the physical pilot.

## Revocation boundary and operation

- Session logout/revoke covers every device linked to that user and closes only the selected account session. The API waits for Hub acknowledgments; RPC failure returns a failure, not a false successful revocation. Retrying session revocation from another active session is idempotent.
- `POST /api/device/revoke-access` takes `{device_id,user_sub}`. Only that device's owner may revoke a non-owner; it cannot remove the owner or the caller. It deletes membership/Push access and awaits user-scoped Hub invalidation. Repeated calls still invalidate matching sockets after the row is already gone.
- The guarantee begins when the revocation API returns success. Bytes sent/buffered before revocation cannot be recalled. Validation that began before invalidation is fenced before forwarding or socket admission.
- **Arbitrary direct D1 SQL edits have no notification hook.** Disabling a user/inventory or deleting ownership directly in the database still relies on the maximum five-minute lease for existing reads (writes check D1 immediately). Use the revocation API for member/session changes. Administrative SQL changes must be paired with the authenticated internal binding's `POST /invalidate-browser` for that user/session; it is not exposed as a public route. Device invalidation remains `POST /invalidate-device`. Instant detection of arbitrary SQL edits would require a supported notification/control-plane flow or D1 polling; telemetry polling was deliberately not added.
- A partial infrastructure/RPC failure cannot promise zero-latency global revocation; API failure and the existing lease are fail-safe fallback boundaries. Do not represent raw SQL mutation or failed API calls as completed realtime revocation.

## Validation

149 Node tests cover original regression and new paused-DB interleavings, bounded queues, persistent retry, ticket storms, ingress limits and immediate API revocation. Nine sanitized runtime targets include the actual HMI admission/Reminder/confirmation/history/ACK-cache implementations. Four targeted mutations reproduce command correlation loss, early Reminder visibility, failed-history advancement and uncertain-terminal-cache poisoning; each compiles and fails the runtime assertions as expected.

Real workerd/native Chromium additionally covers SQLite-backed retry after browser socket replacement and logout closing live WebSocket reads. Existing PWA connection and UX suites cover 12 viewports in both themes. ESP32 DEV/PROD compilation, linked ISR checks, PID/boot/recovery and EEPROM power-cut regressions remain required. Host crypto HALs in C++ fault injection are test doubles; production HMAC vectors/verification are exercised separately by Node and native WebCrypto/workerd tests.

No deployment, OTA release or real-device flash is authorized/performed for this fix. Bench checks must force fast Reminder completion, full trackers/outbox, disconnect at each history chunk/retry phase, expired commands/grants, revoked ownership, slow D1/Cloudflare, and reconnect bursts while measuring control jitter, ISR timing, heap and task stack over the existing 72-hour soak.
